THE HIDDEN FAILURE
03 / 07

What Static Linters
Completely Miss

A page can score 100% on a static DOM scan and still be completely unusable for keyboard and screen-reader users:

⌨️

1. Modal Focus Traps (WCAG 2.1.2)

When a dialog opens, pressing Tab leaks focus into the background page—or Escape fails to return focus to the trigger button.

🔇

2. Silent Async State Changes (WCAG 4.1.3)

Sighted users see a red error toast or updated cart total; screen-reader users hear dead silence without aria-live verification.

⏳

3. Silent Regressions Between Audits

Without a PR merge gate, accessibility fixes degrade within weeks of an annual compliance review.

THE SYSTEMS INVARIANT
04 / 07
THE 3-LAYER CI DEFENSE

Test Semantics, Keyboard
& Spoken Audio in CI

Treat accessibility like unit testing: automated, layered, and enforced on every pull request.

1️⃣

Layer 1: Static DOM Gate (@axe-core/playwright)

Fails the build on any critical or serious WCAG 2.1 AA violation and attaches full JSON traces to the report.

2️⃣

Layer 2: Deterministic Keyboard & Focus Traps

Drives Tab and Escape via Playwright to prove focus stays inside modals and returns to the trigger on dismiss.

3️⃣

Layer 3: Real Screen-Reader Audio (Guidepup)

Automates native macOS VoiceOver to assert what users actually hear on dynamic live-region updates.

Beyond Linters:
Keyboard & Audio Gates

Pair static Axe scans with deterministic interaction and VoiceOver assertions in Playwright.

const results = await new AxeBuilder({ page }).analyze();

✅ Complete: Focus Restoration + Spoken Audio 
// Layer 2: Assert Escape restores focus to trigger
await page.keyboard.press('Escape');
await expect(triggerButton).toBeFocused();

// Layer 3: Assert VoiceOver announces live update
const spoken = await voiceOver.itemText();
expect(spoken).toMatch(/cart updated|1 item added/i);
