THE AUTOMATION ILLUSION

Automated Linters Only Catch
30% to 35% of WCAG Flaws

Running `@axe-core` or Lighthouse in CI is necessary—but dangerously incomplete on its own.

⚠️

What Automated Scanners CAN See

Missing `alt` text tags, raw DOM contrast ratios, missing form labels, duplicate element IDs.

🚫

What Automated Scanners CANNOT See

Keyboard focus traps in modals, logical tab sequences, async ARIA live announcements, screen-reader focus restoration after dismiss.

⚡ The Overlay Widget Myth

Third-party inject plugins (e.g., AccessiBe) do NOT grant legal immunity. Over 900 federal ADA lawsuits in 2024 specifically targeted sites using overlay widgets.

VIOLATION #1 & #2
03 / 07

Keyboard Focus Traps &
Missing Skip Links

WCAG 2.1.2 (No Keyboard Trap) & 2.4.1 (Bypass Blocks) are plaintiff favorites.

❌ The Anti-Pattern: Unconstrained Dialog 
<!-- When open, Tab key escapes the modal into the background DOM -->
<div class="modal-overlay">
  <h3>Confirm Action</h3>
  <button>Cancel</button><button>Delete</button>
</div>
✅ The CI Playwright Test (Deterministic Trap Check) 
await page.getByRole('button', { name: 'Delete' }).press('Tab');
// Focus MUST wrap to first focusable element inside dialog:
await expect(page.getByRole('button', { name: 'Cancel' })).toBeFocused();
💡

Don't Forget the Skip Link

Every page needs an obsidian-contrast `<a href="#main-content" class="sr-only focus:not-sr-only">Skip to content</a>` as its first DOM child.

VIOLATION #3
04 / 07

Invisible Dynamic Errors:
Silent Async Mutations

WCAG 4.1.3 (Status Messages). When an API request fails, sighted users see a red toast—screen reader users hear dead silence.

❌ Sighted-Only Dynamic Banner 
<!-- Screen readers completely ignore dynamic DOM insertions -->
<div class="toast-error">Payment failed: Card expired</div>
✅ Semantic Accessible Live Region 
<!-- VoiceOver & NVDA interrupt to announce error instantly -->
<div role="status" aria-live="polite" class="toast-error">
  Payment failed: Card expired
</div>
🧪

Playwright Verification Rule

`await expect(page.locator('[role="status"]')).toHaveAttribute('aria-live', 'polite')`

VIOLATIONS #4 & #5
05 / 07

Target Size Minimums &
Dark Mode Contrast Drift

WCAG 2.2 Criterion 2.5.8 (Target Size Minimum) & 1.4.3 (Contrast Minimum 4.5:1).

📏

The 24×24px Touch Target Rule

Interactive targets (buttons, icons, menu toggles) must either be at least 24×24 CSS pixels or have sufficient surrounding spacing so circles don't intersect.

🎨

The Dark Mode Contrast Trap

Buttons with white text on sky blue (`#0ea5e9`) only have a 2.77:1 ratio—failing WCAG AA. Obsidian dark themes require high-contrast text (`#030712` on `#ffffff`, ratio 18.7:1) to pass audit scrutiny.

🔍

Subtle Text (#64748b vs #94a3b8)

Slate-500 fails contrast on `#070a12`. Muted text must be upgraded to slate-400 (`#94a3b8`, 7.4:1 ratio) to guarantee compliance.

THE CI AUTOMATION ARCHITECTURE
06 / 07

Automating WCAG Gates in
GitHub Actions with Playwright

Never rely on developer memory. Block regressions at the PR level.

⚡ Zero-Tolerance Accessibility Test Fixture 
import { test, expect } from '@playwright/test';
import AxeBuilder from '@axe-core/playwright';

test('dashboard must pass WCAG 2.1 AA standards', async ({ page }) => {
  await page.goto('/dashboard');
  const results = await new AxeBuilder({ page })
    .withTags(['wcag2a', 'wcag2aa', 'wcag21a', 'wcag21aa'])
    .analyze();

  expect(results.violations).toEqual([]);
});

Execution Time: < 400ms per Route

Axe scans the DOM in-memory. Running this alongside your existing Playwright E2E suite adds zero noticeable CI overhead.
