The CI Flake Feedback Loop

Flaky tests aren't random. They follow a predictable failure cycle:

1

Local Run Passes 100%

Your MacBook M3 has plenty of CPU headroom and an unthrottled browser context.

2

GitHub Actions Runner Throttles

Instead of fixing the DOM race condition, developers inflate timeouts across 150 specs.

4

Pipeline Time Balloons to 35+ Min

Developers stop waiting for CI. They hit "Re-run all jobs" 3 times or bypass checks.

RULE 01 • OBSERVABLE STATE
03 / 06

Never Wait for Time.
Wait for State.

Replace arbitrary timer sleeps with Playwright’s auto-waiting Web-First assertions.

❌ Brittle Sleep (Race Condition Prone) 
// Waits 5s regardless of whether network responded
await page.waitForTimeout(5000);
const visible = await page.locator('.success').isVisible();
expect(visible).toBeTruthy();
✅ Auto-Waiting Web-First Assertion 
// Passes the instant the DOM enters valid state
await page.getByRole('button', { name: 'Confirm Payment' }).click();
await expect(page.getByRole('alert')).toHaveText(/payment confirmed/i);

RULE 02 • RUNTIME ACCELERATION
04 / 06

Stop Logging in via UI
on Every Single Test

Testing the login page 200 times per build is a colossal waste of pipeline runtime.

Legacy Approach
26.6 min
200 specs × 8s UI login flows (filling inputs, clicking submit, waiting for redirect)
Playwright StorageState
< 50 ms
Authenticate once via API setup project, serialize cookies/JWT, inject directly into context
playwright.config.ts 
use: {
  // Every test starts authenticated instantly
  storageState: 'playwright/.auth/user.json',
}

RULE 03 • ZERO SELECTOR CHURN
05 / 06

Ditch Fragile XPaths for
Accessible ARIA Roles

CSS classes change with every Tailwind refactor. Accessible user roles never do.

❌ Fragile DOM Selectors (Breaks on CSS Changes) 
page.locator('div.btn-container > button.sc-1234.btn-primary')
✅ Semantic Accessible Role (WCAG Aligned) 
page.getByRole('button', { name: 'Submit Application' })

💡 The Double Win for Your Team

If Playwright can't find your button by its accessible name, screen reader users can't find it either. You get automated WCAG accessibility auditing for free.
